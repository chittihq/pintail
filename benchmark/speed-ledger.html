Pintail Speed Ledger

Every banked benchmark run, release by release, against MySQL 8.4 and ClickHouse. The analytical suite runs 20,000,000 orders in containers capped at --cpus 8 --memory 8g; the oracle corpus runs every differential case (2,586 in the latest run) at scale 10,000. Each cell is a median and the multiple it represents.

Read the swings with care. Medians move ±10% between runs on a shared host, and some columns were measured on a busier machine than others — v0.0.4-rc1 is the clearest example, where every query reads three to four times its neighbours. v0.1.5-rc6 was measured on a host carrying other work; seven queries improved, but Q6’s minimum rose from 66 to 92 ms while ClickHouse’s held, which the noise rule does not excuse — it is under investigation. v0.1.6 onwards were measured on dedicated 8-vCPU cloud hosts with nothing else running, not on the shared hosts of the earlier columns, so a step between v0.1.5-rc6 and v0.1.6 mixes a code change with a machine change. Against v0.1.6 on the same kind of host, v0.1.7-rc1’s engine track (memo off) is faster on Q6 and Q7. Its Q2 and Q5 cells read slower than v0.1.6’s, but a back-to-back rerun of both releases on one box put them level, so that step is a difference between hosts, not a regression. v0.1.7-rc2 answers Q6 from the settled-result memo, which is why that cell falls from 44 to 9 ms. With the memo off its engine track is ahead of ClickHouse on Q3 to Q8 and behind on Q2 (14 against 9 ms): a filtered count that reads only its predicate column went through the lookup index for a value one row in five holds. That is fixed after the candidate. v0.1.7 was measured on a 16-vCPU host, the stable-release size; the harness caps each engine at 8 CPUs and 8 GB on any host, and its cells sit within a millisecond of v0.1.7-rc3’s 8-vCPU ones. Its release-against-release studies, with the memo off and both releases on one host, put the engine track 75–91% faster than v0.1.6 on every query (Q6 283 to 24 ms, Q8 179 to 17 ms). When a median spikes but the per-query minimum holds, that is host noise, not a regression.

Oracle corpus — extended coverage

The differential corpus is a correctness suite, not a speed benchmark: 2,586 cases built to be semantically hostile. It measures what MySQL-exact semantics cost. In the latest run the first block covers the 2,520 cases Pintail and MySQL both answer; the three-engine block covers the 1,612 all three answer.

ClickHouse is not answering the same suite. In the latest run it errors on 941 of the 2,586 cases and times out on 6, and of the 1,639 it does answer, 468 disagree with MySQL. It is fully correct and participating on 1,144 — under half of the corpus. So the three-engine block compares the engines over the part of the semantic surface ClickHouse accepts, while Pintail answers 2,563 (22 time out at this size, 1 errors) and differs from MySQL on none. 61 are not compared: each of those is a statement with more than one valid answer at this size — a LIMIT over tied sort keys, a GROUP_CONCAT or JSON_ARRAYAGG with no member order, a window numbering tied rows, one case-insensitive group’s spelling — and each of Pintail’s answers was shown to be one of the valid ones.

The 0.1.7 run answers 262 more cases, and they move the totals. The run before it could not load the fixture that 258 timestamp and session time zone cases read, so both engines errored on them; now both answer, and Pintail takes 46.8 s on them against MySQL’s 16.9 s. That is why the multiple of MySQL reads 1.58 against 1.28 and the three-engine block sits level with ClickHouse instead of under half of it. On the 2,071 cases both runs answered, Pintail’s total fell from 42.2 to 32.8 s while MySQL held at 33 s, and the row-constructor family that took 7.9 s now takes 0.16 s.

The latest run changed machines. Runs up to 2026-09-13 used a shared host reached over the network; the 2026-10-02 run used a dedicated 8-vCPU host with a local docker daemon, and 607 more cases. Pintail’s multiple of MySQL reads higher than the run before for two reasons that the totals cannot separate: MySQL answers its sub-millisecond cases faster on a local daemon, and one family of correlated row-constructor comparisons, evaluated once per outer row, takes 7.9 of Pintail’s 43.9 seconds. Compare runs across that step with care; within the run, Pintail’s total over the cases all three answer is under half of ClickHouse’s.
