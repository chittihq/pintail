# M0 skeleton

Pintail now builds as one Rust executable that owns its configuration,
control-plane database, generated secrets, HTTP server, and embedded dashboard
assets. A blank data directory is initialized automatically: SQLite enters WAL
mode, applies metadata schema version 1, and inserts the 256-bit JWT secret
once; the 256-bit DSN-encryption key is saved to an owner-only boot-secret
file. Each generated value is printed only when it is first created. The
server exposes a JSON `/health` endpoint through the prescribed `pintail-api`
boundary and a statically generated Nuxt 4 + shadcn-vue placeholder UI; Bun is
the sole dashboard package manager. Generated assets are ignored and rebuilt
before Rust embeds them. A multi-stage Dockerfile and Compose file exercise the
same binary with persistent storage.

M0 has no MySQL source connector, storage engine, or query engine, so the
database-oracle, replication, and crash-fuzz suites in §13 cannot exercise an
implementation at this milestone. Their CI jobs are added with the milestones
that introduce those surfaces. M0's remote-Docker gate is the release-image
build plus an isolated Compose boot and health check; this report does not
claim that the later §13 matrix is green.

## Gate evidence

- `cargo test --workspace --locked`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo fmt --all -- --check`
- `bun install --frozen-lockfile`
- `bun run typecheck`
- `bun run generate`
- `docker compose config --quiet`
- `docker build --tag pintail:m0 .`
- isolated `docker compose up --no-build` followed by container-health
  inspection and in-container `curl /health` (`{"status":"ok"}`)
