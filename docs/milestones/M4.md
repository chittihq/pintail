# M4 native binlog CDC

Pintail now owns the snapshot-to-stream handoff. `pintail-cdc` registers as a
replica through `mysql_async::BinlogStream`, starts from the M3 checkpoint, and
decodes FULL row images without a CDC framework. MySQL GTID checkpoints use
COM_BINLOG_DUMP_GTID; MySQL and MariaDB file/position streams use the captured
binlog coordinate.

One source transaction remains private until its XID or query commit. MyISAM
rows commit at their statement-end flag. INSERT and same-key UPDATE produce
one versioned row, a key-changing UPDATE produces a tombstone plus its new
row, and DELETE produces a tombstone. GTID sequence or the numeric binlog
file/position plus a 16-bit intra-transaction ordinal supplies deterministic
versions. Append-only tables use that version as a stable synthetic key so a
checkpoint replay cannot allocate a visible duplicate.

Every touched table WAL is synchronized before the corresponding GTID or
file/position is committed to SQLite. A crash in between can replay rows, but
the same key/version is invisible under merge-on-read. Transient source
disconnects use bounded exponential backoff and reopen from that durable
coordinate.

Decode failures become idempotent SQLite DLQ entries. Pintail discards every
pending mutation for the affected table in that source transaction, leaves
its `needs_resync` state sticky across restarts, and continues committing
unrelated tables. The shared snapshot mapper keeps zero dates, decimals,
JSON, binary values, ENUM/SET, BIT, timestamps, utf8mb4, and latin1 consistent
between M3 and M4.

File/position streams preflight the captured coordinate against `SHOW BINARY
LOGS`, because MySQL can return an empty non-blocking stream instead of error
1236 for a missing filename. A missing file, an offset past its retained size,
or error 1236 marks every included table for resnapshot. Default one-shot
recovery publishes an empty table generation, resets the old snapshot journal
and handoff, runs a new consistent snapshot, and resumes CDC. Reader snapshots
that pinned the old generation remain valid until released.

## Gate evidence

- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo test --workspace --locked`
- `cargo test -p pintail-cdc --test mysql_cdc -- --ignored --nocapture
  --test-threads=1`
- `cargo test -p pintail-sqllogic --test plan_quality`
- `cargo test -p pintail-sqllogic --test mysql_oracle -- --ignored --nocapture`
- `bun install --frozen-lockfile`, `bun run typecheck`, and
  `bun run generate` in `packages/dashboard`

The live CRUD/type gate exercises MySQL 8.4 GTID, transaction buffering,
tombstones, GIPK, append replay, the M4 type matrix, and a deliberately
unsupported utf16 row followed by a successful transaction on another table.
The failed row is present once in the DLQ and only its table is quarantined.

The compatibility gate repeats CDC against MySQL 8.4 file/position, MySQL 5.7
file/position, and MariaDB 11's file/position fallback. It includes
transactional CRUD, zero temporal normalization, decimal/ENUM/SET/BIT/binary
fidelity, and three independent MyISAM statements.

The restart gate starts a paced 200-row writer, SIGKILLs a separate CDC worker
after ten durable progress callbacks while the writer is still active, and
reopens the same stores. The final replica has exactly 200 rows and an ID sum
of 19,900. A separate rewind test replays an already durable checkpoint and
proves append inserts remain singletons.

The purge gate rotates and deletes the captured MySQL 8.4 file, verifies
durable `needs_resync`, reopens the old target, and lets default automatic
recovery rebuild both source rows from a fresh snapshot.
