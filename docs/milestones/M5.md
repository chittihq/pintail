# M5 DDL evolution and polling

Pintail now converges sources that cannot expose a usable row binlog. One
polling cycle selects an inclusive timestamp/created/auto-increment cursor when
available, otherwise uses durable source-side aggregate chunk fingerprints for
keyed tables or replaces the complete generation for append-only tables. Poll
versions are monotonic, changed rows use scan-mode no-op suppression, and every
row WAL is synchronized before its cursor, version, and fingerprints advance
in SQLite.

Count plus maximum cursor/key remains a cheap activity signal, but it is not a
correctness gate. Even when that token is stable, Pintail rereads the cursor
boundary, compares checksum chunks, or checks the append generation. Scheduled
composite-safe key reconciliation emits tombstones for absent source keys.
Secondary-UNIQUE audits issue targeted source lookups and tombstone only the
stale colliding primary key; an optional read policy hides the lower-version
row during that short repair window. Operator-selected soft-delete columns
become tombstones during normal cursor sync.

The same scheduled reconciliation can compare complete rows for probe-flagged
cascade/SET NULL child tables while their database remains in CDC mode. Its
version is chosen above the table's current live CDC maximum and it never
advances or replaces the binlog checkpoint.

CDC query events now feed a MySQL DDL classifier and durable schema history.
Pure ADD/DROP COLUMN changes preserve stable column IDs and publish compatible
live store schemas; old readers remain pinned to their original generation.
TRUNCATE publishes an empty generation. Rename, type, physical-key, and other
conservative ALTER cases quarantine only their table. DROP retains an orphaned
replica, while a matching CREATE opens a hashed table directory, snapshots it,
and joins the active stream.

## Gate evidence

- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo test --workspace --locked`
- `cargo test -p pintail-poll --test mysql_poll -- --ignored --nocapture`
- `cargo test -p pintail-cdc --test mysql_cdc
  ddl_evolution_add_drop_rename_create_truncate_and_orphan
  -- --ignored --nocapture`
- `cargo test -p pintail-cdc --test mysql_cdc
  cdc_cascade_negative_control_and_scheduled_repair
  -- --ignored --nocapture`
- `cargo test -p pintail-sqllogic --test plan_quality`
- `cargo test -p pintail-sqllogic --test mysql_oracle
  -- --ignored --nocapture`
- `bun install --frozen-lockfile`, `bun run typecheck`, and
  `bun run generate` in `packages/dashboard`

The MySQL 8.4 binlog-disabled gate covers cursor CRUD, cursor-less keyed and
composite-key updates/deletes, append replacement, soft deletion, secondary
UNIQUE reuse, the exact count-neutral same-MAX blind spot, and ten forced idle
cycles with byte-identical table storage.

The live DDL gate covers ADD and DROP with post-change writes, reopen from
durable stable IDs, table-local rename quarantine, TRUNCATE followed by new
CDC, matching CREATE auto-snapshot, and retained DROP data. The cascade gate
demonstrates missing child delete and update events as negative controls before
scheduled repair and verifies that CDC mode and its source checkpoint are
unchanged.
