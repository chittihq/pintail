# M3 source probe and snapshot engine

Pintail can now inspect real MySQL and MariaDB sources, choose CDC or polling
from server variables and grants, map source schemas without guessing from
row values, and copy tables into immutable PTSEG segments. Primary keys,
composite keys, the first safe UNIQUE fallback, MySQL generated invisible
primary keys, and append-row-id tables are all represented explicitly.
Virtual generated columns are skipped; stored generated columns are copied.

The coordinator acquires `FLUSH TABLES WITH READ LOCK`, captures GTID or
binlog file/position, starts parallel repeatable-read consistent snapshot
transactions, and releases the lock before bulk copying. Tables use keyset
pages when they have a stable key and a single offset stream otherwise.
Every chunk is converted to version zero, sorted, written directly to PTSEG,
published through the manifest, and only then marked complete in SQLite.

Resume skips completed chunks and may safely replay a segment whose journal
write was interrupted because merge-on-read is always enabled. Crucially, the
first captured handoff position is retained across attempts, so M4 CDC can
replay changes made while the snapshot process was down. Progress reports
durable rows, converted bytes, and an ETA based on source statistics.

The schema mapper retains integer widths, decimal precision/scale, temporal
fractional precision, charset/collation metadata, JSON identity, and source
type declarations. Zero and out-of-range dates and date-times become `NULL`
at decode. PTSEG version one retains its existing physical carriers; the
exact logical type remains in the schema fingerprint and is validated through
store reopen and executor batches.

## Gate evidence

- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo test --workspace --locked`
- `cargo test -p pintail-snapshot --test mysql_snapshot
  m3_snapshot_basic_resume_type_fidelity_and_pk_matrix -- --ignored --nocapture`
- `cargo test -p pintail-snapshot --test mysql_snapshot
  snapshot_compatibility_matrix_covers_file_position_mariadb_and_polling_sources
  -- --ignored --nocapture`
- `cargo test -p pintail-sqllogic --test plan_quality`
- `cargo test -p pintail-sqllogic --test mysql_oracle -- --ignored --nocapture`
- `bun install --frozen-lockfile`, `bun run typecheck`, and
  `bun run generate` in `packages/dashboard`

The primary Docker gate creates ten 100,000-row fact tables, checks every
source count, integer sum, and CRC32 against Pintail, then kills a real child
snapshot process after durable progress and resumes a separate 100,000-row
table without visible duplicates or gaps. The same run covers the M3 type
matrix and primary/composite/UNIQUE/append/GIPK strategies.

The compatibility gate passes MySQL 8.4 file/position, MySQL 5.7
file/position, MariaDB 11 GTID, and MySQL 8.4 with binary logging disabled.
M3's deliberate carrier, degraded-lock, and PK-less resume boundaries are
listed in [`docs/limitations.md`](../limitations.md).
