# M9 hardening and release

M9 closes the v1 release boundary with bounded streaming reads and compaction,
oversized-transaction spill, a deterministic 30-minute CDC soak, Duckling's
20-million-order analytical benchmark, an explicit Duckling known-limit audit,
and two consecutive passes of the complete release matrix. The product source
was unchanged between the two matrix passes; this report and its README and
changelog links were added afterward.

## Performance gates

- The [analytical benchmark](../../benchmark/results.md) loaded exactly
  20,000,000 orders into MySQL 8.4, Pintail, and ClickHouse 25.8. Across the
  same eight queries, MySQL took 3,841,437 ms, Pintail took 22,205 ms, and
  ClickHouse took 5,191 ms. Pintail's 173.0× aggregate speedup passed the
  required 50× gate; ClickHouse remains an informational reference.
- The [CDC soak](../../tests/loadgen/results.md) ran for 1,800.0 seconds and
  generated 9,898,625 events at 5,499.2 events/s. It converged on identical
  2,576,375-row source and replica checksums with zero DLQ, at most 27 seconds
  of lag, 291.2 MiB peak RSS, a 126.6 MiB last-third average, and a fitted
  46.6 MiB/hour RSS slope. All nine enforced gates passed.

## Consecutive release matrix

The following matrix passed twice consecutively:

- frozen Bun dashboard dependency install, typecheck, and static generation;
- Rust formatting, strict workspace Clippy, and locked workspace tests across
  all targets and all features;
- plan-quality pruning assertions and all 600 MySQL 8.4 oracle queries;
- the one-million-row snapshot SIGKILL/resume gate and the MySQL 5.7,
  MySQL 8.4, MariaDB 11, GTID, file-position, and polling snapshot matrix;
- all eight serial CDC cases, including sustained-write SIGKILL recovery,
  transactional visibility, type fidelity, DDL evolution, binlog purge,
  cascade repair, and MyISAM/file-position compatibility;
- polling CRUD, delete-blindspot repair, secondary-UNIQUE reuse, cascade
  repair, and unchanged-data storage invariance;
- MySQL 8.4 CLI, mysql2 under Bun, PyMySQL, and Rust wire clients;
- full and incremental MinIO backup with checksum-verified side-by-side
  restore, plus all three ignored API integration cases;
- a clean production Compose build, non-root runtime and health check; and
- a real-browser first-boot and database wizard, CDC capability probe,
  snapshot-to-streaming transition, and typed SQL query. The query returned
  the exact two source rows, every captured API response succeeded, the
  390×844 layout had no horizontal overflow, and the browser reported zero
  console errors and zero warnings.

Every matrix container, volume, network, browser session, and generated
client-install directory was isolated per pass and removed afterward.

## Release boundary

The [limitations](../limitations.md) audit accounts for every known limitation
published by Duckling: each is either fixed by Pintail's native ownership
model or explicitly inherited with an architectural reason. Pintail v1 remains
a single-node, read-only analytical replica; it does not claim clustered query
execution, synchronous high availability, source writes, multi-tenant
isolation, TLS termination, exact decimal arithmetic, spatial querying, or
query spill-to-disk.
