# M8 operations

Pintail now supervises each eligible database independently, running bounded
CDC or polling cycles, retrying failures without stalling healthy mirrors, and
launching due backups after successful cycles. The public Prometheus endpoint
reports query, replication, lag, storage, compaction, memory, DLQ, and backup
signals. DLQ records can be retried through a table reconciliation and are
removed only after that repair succeeds.

Backup configuration and run history are durable control-plane records.
Credentials are encrypted at rest. Full and incremental jobs pin table
snapshots, upload checksum-addressed immutable manifests and segments to
S3-compatible storage, reuse unchanged segment objects, and publish the backup
manifest last. Restore verifies every object with SHA-256 in a staging
directory before atomically publishing a new, detached, queryable database
beside the source. Source DSNs are deliberately excluded; restored databases
need new source credentials before ingestion can resume.

The dashboard exposes destination and cadence configuration, manual and forced
full jobs, recovery history, restore-as, live metrics, supervisor policy, and
retry-before-discard DLQ controls. Its bucket prefix validation is an accident
guard against dangerously broad object paths, not tenant isolation or an
authorization boundary. Scheduled backups run only for eligible databases
after a healthy supervisor cycle.

## Gate evidence

- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo test --workspace --all-features --locked`
- `cargo test -p pintail-backup --test minio_restore -- --ignored --nocapture`
- `cargo test -p pintail-api --test mysql_api
  three_database_supervisor_contains_one_source_failure
  -- --ignored --exact --nocapture`
- `bun install --frozen-lockfile`, `bun run typecheck`, and
  `bun run generate` in `packages/dashboard`
- Playwright checks of Backups, Activity, database DLQ controls, and Settings
  at desktop and 390-pixel mobile widths with no console errors, warnings, or
  horizontal overflow

The MinIO gate creates a full and incremental recovery chain, verifies one
unchanged segment is reused, then downloads and checksum-verifies both segment
generations during restore. The multi-database gate snapshots three distinct
MySQL 8.4 sources in mixed CDC and polling modes, stops one source, and proves
that the other two continue completing supervised cycles and serving their
rows while only the failed database enters its durable error state.
