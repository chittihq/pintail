# M1 storage core

Pintail now owns a durable single-writer table engine: typed batches enter a
checksummed WAL, become visible through an immutable memtable snapshot, flush
into versioned columnar PTSEG files, and are published by a checksummed atomic
manifest. Reopen verifies live footers, repairs torn WAL tails, removes
unpublished segment orphans, and merges memtable plus segments by primary key
and maximum source version.

PTSEG version 1 includes dense null bitmaps, all five required block
encodings, LZ4 and zstd compression, per-block checksums, typed zone maps,
64-register HLL sketches, sparse primary-key indexes, a bloom filter, schema
fingerprints, version bounds, and a checksummed random-access footer. The
complete binary contract is in [`docs/format.md`](../format.md).

Size-tier compaction selects similarly sized overlapping segments, exposes
byte debt, retains tombstones in partial merges, drops them in a full merge,
and writes the coldest full-merge output with zstd. Reader-owned manifest
generations delay obsolete-file reclamation. Nullable additive schema changes
are metadata-only for old segment and WAL rows; dropped bytes disappear when
compaction rewrites them.

The catalog key fallback is explicit in the schema: primary, first UNIQUE, or
generated append-rowid. Crossing the configured memtable byte budget performs
one bounded flush/compaction maintenance step before ingestion returns.
The storage metrics surface reports memtable bytes, live segment count, and
compaction debt. Compaction yields between input segments so it does not
monopolize an executor thread.
Manifest key bounds and bloom filters prune unrelated segments for point and
inclusive range reads before block decoding.
Projected range scans apply checksummed key-block zone maps and decode only
the requested user columns after key/version/tombstone resolution.

## Gate evidence

- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo test --workspace --locked`
- 100 deterministic process-kill/reopen crash-fuzz iterations spanning WAL
  append, flush, manifest swap, and compaction
- 64 deterministic randomized compaction cases compared with a naive
  max-version/tombstone reference model
- focused tests for torn WAL repair, stale pre-truncation WAL, orphan segment
  cleanup, footer/block corruption, every block encoding and scalar type,
  schema evolution, pinned snapshots, and delayed file reclamation

M1 does not claim the later query, MySQL protocol, CDC, snapshot, polling,
backup, or benchmark gates. Those surfaces begin in their named milestones.
